# Player Guide — PROJECT PHANTOM

## What this is
PROJECT PHANTOM is a local web-based CTF exercise using fictional records, accounts, and archive artifacts. It contains three sequential stages and four intentional vulnerability categories.

## Requirements and startup
Install Docker Desktop, extract the project, open PowerShell in the project folder, run `py scripts/init_env.py`, and keep the generated password shown by the script. Start with `docker compose up --build -d`, then visit <http://127.0.0.1:8787>. Sign in with username `phantom` and the generated password. The `.env` file contains private local settings and should not be shared.

## Dashboard and stages
The dashboard shows progress, stage locks, elapsed time, hint usage, and recent runs. Begin a run using **Initialize challenge**. Stage 1 investigates credential leakage in the provided deployment notes. Stage 2 contains an IDOR records exercise and a controlled CSRF role-change exercise. Stage 3 contains a safely simulated archive path traversal exercise. Stages unlock only after the previous flag is verified.

## Flags
Open **Flag verification terminal**, choose the available stage, and submit the flag found through your lab investigation. The server validates flags. Stage 2 requires both exercises to be completed; Stage 3 requires archive evidence retrieval. The guide does not contain flag values or solutions.

## Timer and hints
The timer is derived from server timestamps and continues across refreshes. It stops when the final flag is accepted. Two hints are available per run by default. Hint usage is recorded.

## Stop, restart, troubleshooting
Stop with `docker compose down`; progress remains in the Docker volume. Restart with `docker compose up -d`. If port 8787 is in use, change the host-side port in `docker-compose.yml`. If login fails, check the password generated by `scripts/init_env.py`; running that script again does not replace an existing `.env`. Check container output with `docker compose logs --tail=100` and health at `/health`. To reset all progress, back up anything needed and use `docker compose down -v`; this deletes the named data volume and prior run history.
